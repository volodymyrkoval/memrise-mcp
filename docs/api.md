# Memrise API notes

Behaviour of the unofficial Memrise web API (`/v1.25`) that this project relies on. Generated by `npm run probe`, then trimmed to what the code depends on.

## Authentication

- Obtain a CSRF cookie via `/v1.25/web/ensure_csrf` (fallback: `/signin`).
- Exchange credentials at `/v1.25/auth/access_token/`, then create a web session at `/v1.25/auth/web/`.
- Data endpoints accept the Bearer token alone; cookies are optional.
- `x-csrftoken` mirrors the `csrftoken` cookie.

## Language pairs

- `GET /v1.25/me/language_pairs/` returns `language_pairs`, each with `language_pair_id`, source and target language names and locales.

## Learnables

- `GET /v1.25/me/language_pairs/{pair}/learnables/` takes `learning_state`, `page_size` and `next_page_token`.
- Accepted `learning_state` values: `FULLY_LEARNED_OR_KNOWN`, `ANY`. Values are case-sensitive and the parameter is required.
- `ANY` is a superset of `FULLY_LEARNED_OR_KNOWN`.
- Pagination: follow `next_page_token` until it is absent. `page_size` has a server-side maximum; larger values return 400.

## Scenarios

- `GET /v1.25/me/language_pairs/{pair}/scenarios/` takes `scenario_type` (`completed`, `in_progress`), `limit` and `offset`, and returns `scenarios`, `total_number` and `has_more_pages`. `limit` has a server-side maximum.
- `has_immerse_content` does not change `total_number`.
- `GET /v1.25/me/scenarios/{id}/details/` lists the scenario's learnables. Each `learnable_id` equals a learnable's `learnable_id_key`; join on it.

## Headers

Requests mimic a browser: `accept`, `origin`, `referer`, `x-client-type`, `x-timezone`, `x-device-type`, `x-os`, `x-os-version`, `x-browser`, `x-browser-version`, `x-correlation-id`, `content-type`, `x-csrftoken`.
